# Examples

Each folder holds an `input.md` with raw, messy source material and an `expected-output.md` with the response the agent should produce under the default configuration. Every company, person, system, and document in these examples is fictional.

Use them to try the agent on a new platform and to check that a change to the instructions still produces the right output.

| Example | Industry | Request type | What it demonstrates |
| --- | --- | --- | --- |
| [logistics-feed-change](logistics-feed-change) | Logistics | Change to existing | A partner file schedule change, conflicting dates, a shared file that affects other partners, and a related prior intake |
| [clinic-scheduling-integration](clinic-scheduling-integration) | Healthcare | New capability | A new system connection, a requested date that falls before the vendor can finish, and a tester nobody named |
| [permit-portal-change](permit-portal-change) | Public sector | Compliance-driven | A new form field required by an ordinance, a fix stated without the outcome, and no scope boundary |
| [supplier-file-change](supplier-file-change) | Manufacturing | Data or report | An inbound file layout change with no field list, an external testing gap, and a `Needs answers` verdict with no blockers |
